<objective>
## Goal
Habilitar que un invitado confirme su asistencia directamente en la landing pública (nombre libre + cantidad), guardando la respuesta en una tabla nueva `public_rsvps` en Supabase, con RLS que permita insertar de forma anónima pero restrinja lectura/borrado al admin autenticado.

## Purpose
Es el primer paso del cambio de rumbo hacia el envío masivo por WhatsApp: para poder mandar un único mensaje/link idéntico a muchos contactos, la confirmación tiene que vivir en la landing con un link genérico (modelo latarjetadigital.app), en lugar del link único `/invite/:code` con cupos pre-asignados. Este plan entrega el flujo de confirmación end-to-end del lado del invitado.

## Output
- Migración SQL que crea `public_rsvps` + políticas RLS.
- Tipo `PublicRSVP` y funciones `submitPublicRSVP` / `listPublicRSVPs` / `deletePublicRSVP` en la capa de queries.
- `RSVPSection` nueva en la landing (form nombre + cantidad + asiste/no, lee `?n=` para pre-llenar el saludo, confirmación inline).
- `HomePage.tsx` monta la nueva sección.
</objective>

<acceptance_criteria>

## AC-1: Confirmación pública desde la landing
```gherkin
Given un invitado abre la landing con el link genérico
When completa su nombre, indica si asiste y (si asiste) la cantidad de personas, y envía
Then la respuesta se guarda en public_rsvps
And ve una confirmación inline (sin recargar) agradeciendo
```

## AC-2: Pre-llenado por query param
```gherkin
Given la landing se abre con ?n=Leonardo (nombre URL-encoded)
When se monta la sección de RSVP
Then el saludo/campo de nombre aparece pre-llenado con "Leonardo"
And si no viene ?n=, el campo arranca vacío y es editable
```

## AC-3: Seguridad por RLS (insert anónimo, lectura/borrado solo admin)
```gherkin
Given la tabla public_rsvps con RLS activada
When un cliente anónimo (anon key) intenta INSERT
Then la operación es permitida
And cuando ese mismo cliente anónimo intenta SELECT o DELETE
Then la operación es rechazada por RLS
And un cliente autenticado (admin) puede SELECT y DELETE
```

## AC-4: Validación y estados del formulario
```gherkin
Given el formulario de RSVP en la landing
When el invitado intenta enviar sin nombre
Then se muestra un error de validación y no se envía
And durante el envío el botón muestra estado "Enviando…" y queda deshabilitado
And si el insert falla, se muestra un mensaje de error y permite reintentar
```

      - id uuid primary key default gen_random_uuid()
      - name text not null
      - attending boolean not null default true
      - seat_count int not null default 1 check (seat_count >= 1)
      - dietary text not null default 'ninguna'
      - created_at timestamptz not null default now()

      - INSERT: permitido al rol anon (with check true) — cualquiera con el link confirma.
      - SELECT: permitido solo a authenticated (admin).
      - DELETE: permitido solo a authenticated (admin).
      - (No UPDATE por ahora.)
    Índice por created_at desc para el listado del admin.
    Avoid: exponer SELECT a anon (filtraría todas las confirmaciones al público).
  </action>
